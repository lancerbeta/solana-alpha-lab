# Атомарная запись PaperPlane

Смена состояния PaperPlane больше не расходится с событиями, которые её описывают. Условное обновление и порядок вставки закрывают потерянное обновление и случайный порядок внутри одной секунды.

База контракта перепривязана на текущий `origin/main` `ac5b761e4746cebc81b416a843a8a23080d71649` по явному решению владельца. Предыдущая привязка `ae678372f2a96fbc20c519c23905ae5c44332458` разошлась с main в `catalog/assets/core.yaml` (шесть чужих хешей целостности). Эти хеши сохранены. Байты `paper_plane.py`, `paper_shadow_commands.py` и вертикального теста совпали с уже просмотренной реализацией.

| Было | Стало |
| --- | --- |
| `transition` читал состояние и писал его без условия, каждая команда сама коммитилась | `BEGIN IMMEDIATE`, повторное чтение, `UPDATE ... AND state=?`; иначе `STALE_STATE:<from>-><to>` |
| События дописывались после коммита состояния | События смены состояния пишутся в той же транзакции |
| Команда оператора и запись идемпотентности жили отдельно | Одна транзакция |
| `execution_events` сортировались по `created_at, event_id` | `ORDER BY rowid` |

Гонка закрытия против exit-fill: 500 итераций, 0 сбоев. Время теста 25.492 с, стена 26.37 с. Модули домена исполнения: 126 тестов, 2 пропуска, 0 падений, 59.340 с. `EXECUTION_DOMAIN_FAST_TESTS` — PASS.

Проекция Trading Operations на фикстуре учёта `SIGDEC-T-P1..P3`: streak `2`, просадка `30.37`, нетто `9.79` / `-10.19` / `-20.18`. Обратный порядок событий не меняет first-wins скаляры. Штамп `CONFLICT_REASON` на том же `created_at` меняет выигравшую причину, так что проверка не пустая.

Схема не менялась. Тесты не удалялись и не ослаблялись. В этом PR статус серии в дизайн-файле не помечен как `A1 MERGED`.

Ограничения: `VACUUM` может перенумеровать `rowid`; порядок после копирования файла checkpoint сохраняется, после упаковки — нет. `rowid` — порядок вставки в живом файле. Приём решения и fill-хвост — две транзакции: крах после приёма оставляет `WATCHED` без intent, крах внутри fill откатывает открытие вместе с событиями. `busy_timeout` остаётся 5 с.
