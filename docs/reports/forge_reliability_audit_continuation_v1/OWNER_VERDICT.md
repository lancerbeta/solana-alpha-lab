# Forge: ограниченно пригодна, полная надёжность не доказана

Обычные offline-пути исполняются, сохраняют отрицательный терминал, удерживают
историю и восстанавливают pending-запрос. Пользоваться ими можно в пределах
поддерживаемых consumer и frozen policy. Обещать процесс без ручного ремонта на
каждом шаге пока нельзя: текущий native проход потребовал исправления формы
`confounders`, а проверка frozen гипотезы на более позднем cohort не поддержана.
На 400 synthetic records один холодный readout занимает 38,17 с.

В этом PR исправлен только обход PREVIEW: два различных frozen запроса с
одинаковым payload теперь занимают два слота. Третий запрос отклоняется до
допуска; повтор остаётся `REPEAT`, pending переходит в completed без нового
списания. История, defaults и RSS limits сохранены. BASE дефект воспроизведён
2/2, тот же POST_REPAIR сценарий — 2/2 с корректным отказом.

`confounders`, отсутствие chronological consumer и runtime-fingerprint seam
сохранены отдельными findings; второго ремонта нет. Ни synthetic result,
ни KILL, ни same-data replay, ни CI не дают alpha/confirmation/PROMOTE.
Следующее продуктовое решение: отдельно определить контракт проверки frozen
гипотезы на новых данных. Перед новым реальным native проходом также нужен
отдельный transport repair для `confounders`. Этот audit их не выполняет.

Основные доказательства: [EVIDENCE_INDEX.md](EVIDENCE_INDEX.md).

готовности gate. Доставка завершается guarded merge и проверкой точного `main`.

для группы 4 этого PR; постоянные лимиты остальных запусков сохранены.
