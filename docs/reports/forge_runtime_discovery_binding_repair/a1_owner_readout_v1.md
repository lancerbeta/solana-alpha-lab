# FORGE_RUNTIME_DISCOVERY_BINDING_REPAIR_V1

Ordinary discovery admission now comes from the published labels contract.
`discovery-binding` does not read parquet values. A missing `holdout` boolean
on an already published discovery corpus is derived only when `REQUIRED_LABELS`
match and no protected holdout assignment is present.

Memory outcome: `SCOPED_MEMORY_REPAIR`. Recoverable scope from immutable cycle records reaches both Prompt A `ranked_prior_entries` and Critic capsules. A shared discovery scope is not written onto every hypothesis. A runner-up packet keeps only scope proven on that candidate. When that scope is not the scope the discovery look was computed for, the packet drops the primary result and result hash, drops the primary prior relations, and records prior relations only for the runner-up's own complete scope. A later critic PASS on that runner-up cannot become a scientific pass without its own linked look; classify returns `KILL_UNBOUND_EVIDENCE` with `GROUNDED_RESULT_UNBOUND`. That recorded terminal stays, and the next memory snapshot treats it as `TECHNICAL_STOP`: Prompt A and Critic do not mark it `HARD_CLOSE`, and the same scope does not raise `EXACT_PRIOR_SCOPE_MATCH`. Prompt A says a technical refusal is not a negative market result. A look keeps the population and the latest decision point the spec computed. Its confirming target is that spec's target point and field, not a free-text label. A repeated spec cannot rename that result. A selected card with a different population or a different decision moment stops before a scientific record. A card that changes or adds a target, estimand, or other label is saved as a narrower idea and cannot take a PASS or a scientific close on that look. A revision rebinds the card to the look, so a changed scope does not keep a confirming result. A card that matches the stored population, latest decision point, and measured target keeps the result and the ordinary classify path. A scientific `KILL_MECHANISM` on a scope the look actually confirms still blocks. A valid same-scope close still blocks. `PARK`, `NOT_SELECTED`, `NO_WORTHY` and technical stops (`OBSERVABILITY_BLOCKED`, `INPUT_NOT_READY`, `HOLDOUT_UNRESOLVED`, `KILL_UNBOUND_EVIDENCE` / `TECHNICAL_STOP`) do not ban a family.
