# Forge research-universe policy

New Forge runs require an active research-universe profile in ResearchStore. The active snapshot (`semantic_sha256`, minimum holders, minimum liquidity, and the meaning of the eligible population) is always present in `FORGE_CONTEXT_PACKET` before Prompt A. The owner changes those minima with preview, apply, and status. The first intended profile is 50 holders and 5000 USD liquidity, both at decision time. Changing 5000 to 20000 is the same three commands.

A missing profile stops new synthesis: `forge_runnable=false`, `UNIVERSE_POLICY_REQUIRED`, and `forge_input_next=PREVIEW_THEN_AUTHORIZED_APPLY`. That is not a missing corpus. A damaged profile uses its typed code and `RESTORE_RESEARCH_UNIVERSE_PROFILE_THEN_RETRY`. An already saved result, frozen replay, and recovery stay readable without today's profile. An open operation must be finished before apply. A published corpus whose logical content hash or caller binding hash does not match writes nothing. A frozen recipe replays its own snapshot. Returning to the same profile and the same rows does not spend a new main look.

This atom does not activate the live profile and does not take a main look.
