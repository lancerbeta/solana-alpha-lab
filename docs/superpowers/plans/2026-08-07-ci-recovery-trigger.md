# CI_RECOVERY_TRIGGER_V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one parameterless, read-only manual recovery trigger to Repository validation so an operator can recover from a lost GitHub webhook without a no-op commit.

**Architecture:** The existing workflow remains one job with the same pins, permissions and validation command. `scripts/validate_ci.py` expands its exact trigger contract from two triggers to three, and `tests/test_ci.py` proves that only the no-input manual trigger is newly accepted. Catalog records remain hash-bound and generated navigation is regenerated by the existing script.

**Tech Stack:** GitHub Actions YAML, Python 3.13 standard-library `unittest`, PyYAML BaseLoader, existing Catalog generator and validator.

## Global Constraints

- Add only `workflow_dispatch:` with no inputs, environments or secrets.
- Preserve `contents: read`, immutable action pins, disabled credential persistence, full fetch depth, timeout and concurrency contract.
- Reject `workflow_dispatch.inputs`, `pull_request_target`, secrets, write/id-token permissions, caches and artifacts.
- Add no dependencies, provider/API/RPC/WSS calls, wallet/signer/transaction activity, deployment, spend, Project Sources mutation or task-status claim.
- Generated Catalog files are produced only by `scripts/generate_navigation.py --write`.
- One real manual GitHub Actions dispatch is permitted only after ordinary PR CI passes, on the PR branch, and never on `main` before merge.
